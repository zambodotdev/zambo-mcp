# Security Policy

## Reporting a vulnerability

Do not open a public issue for exploitable vulnerabilities, exposed credentials, payment bypasses, ownership failures, or private-data leaks. Use the private contact path at [zambo.dev](https://zambo.dev) and include the affected endpoint, impact, reproduction steps, and whether the issue was tested against production.

Never include real secrets, private keys, tokens, personal data, or destructive proof-of-concept payloads in a report.

## Scope notes

This repository documents the public remote MCP service. Security claims are limited to behavior that can be independently observed or tested. External providers and client applications have their own security boundaries.
